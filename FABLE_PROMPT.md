## 1. Что уже есть (текущее состояние)

**Идея:** соцсеть образов. Пользователь выбирает манекен (мужской/женский), перетаскивает на него вещи из каталога, масштабирует/вращает/меняет слои, публикует образ с описанием и хештегами. Другие пользователи видят ленту, лайкают, комментируют, подписываются, переписываются в личке, делятся постами в чатах. У каждой вещи в посте — описание и ссылка «где купить».

**Стек сейчас:** Django 4.2 + DRF, PostgreSQL 16, Redis, Django Channels + Daphne (WebSocket), Cloudinary для медиа, фронт — Django Templates + vanilla JS (SPA-подобная подгрузка через `loadPage`), Remix Icon. Docker Compose (db, redis, backend). Авторизация — проверка `initData` Telegram WebApp (`backend/api/utils.py`), дальше сессия с `telegram_id`.

**Модели** (`backend/api/models.py`): `TelegramUser`, `Follow`, `Dialog` (user1<user2, pinned), `Message` (is_read, edited), `Mannequin` (gender, image), `ClothingCategory` (8 категорий: top, shirt, pants, dress, skirt, shoes, accessories, hat; icon_class/icon_svg, order), `ClothingItem` (category, name, image, gender, style, color, tags, item_description, buy_link; сжатие изображения в `save()`), `Hashtag`, `OutfitPost` (mannequin_type, description, hashtags M2M, final_image, likes_count), `PostClothingItem` (position_x/y, scale, rotation, z_index), `PostLike`, `PostComment` (likes_count), `CommentLike`, `Notification` (like/comment/follow). Мусор: неиспользуемые `CustomUser`, `Post`.

**API** (`backend/api/urls.py`, `views.py`, `views_constructor.py`): authorize, поиск пользователей, follow toggle, connections (following/followers/friends), диалоги (список, создание, сообщения, edit/delete, pin/delete диалога), манекены, категории, вещи (фильтр category/gender/style/color, лимит 30), создание образа, посты пользователя, лайк поста/комментария, комментарии, поиск постов по хештегу/описанию, удаление поста, лента главной (подписки вперемешку с популярными + since_id-поллинг новых), уведомления, детали поста, аватар (цвет / из Telegram / загрузка / удаление).

**WebSocket** (`backend/api/consumers.py`): `ws/chat/<dialog_id>/` (сообщения, редактирование, удаление), `ws/dialogs/` (обновления списка диалогов).

**Фронт** (`frontend/static/js`): `constructor.js` (~1000 строк: drag, pinch-zoom, rotate двумя пальцами, resize-хэндл, undo/redo на 50 шагов, z-index вверх/вниз, фильтр по стилю, рендер итоговой картинки в `<canvas>` на клиенте, публикация), `home.js` (вертикальная лента-слайды, уведомления, комментарии), `posts.js` (сетка постов профиля, просмотрщик, выделение и массовое удаление, карусель вещей образа, шаринг в диалоги), `messages.js` (мессенджер), `search.js`, `connections.js`, `avatar.js`.

**Известные проблемы, которые обязательно исправить в новой версии:**
- Секреты в git: токен бота и пароль БД захардкожены в `backend/config/settings.py`, `backend/.env` закоммичен, `SECRET_KEY` insecure, `DEBUG=True`, `ALLOWED_HOSTS=['*']`. → Токен бота считать скомпрометированным: в `docs/` напиши инструкцию перевыпустить его через @BotFather.
- Все API — `csrf_exempt` + `AllowAny` + ручная проверка сессии в каждом view; дублируется `get_current_user`.
- **WebSocket доверяет `sender_id` от клиента** (`consumers.py`, `save_message`/`edit_message`/`delete_message`) — можно писать от чужого имени. Отправитель должен браться только из аутентифицированного scope.
- N+1: `p.comments.count()` на каждый пост в `_serialize_post`, `last_message`/`unread` на каждый диалог. Нет пагинации нигде (жёсткие `[:30]`, `[:40]`, `[:50]`).
- Гонки счётчиков: `likes_count += 1` вместо `F()`/агрегатов.
- Даты отдаются уже отформатированными строками (`'%H:%M'`), без таймзоны; `TIME_ZONE='UTC'`, `LANGUAGE_CODE='en-us'`.
- Шаринг поста в чат — строка `[post:{json}]` внутри текста сообщения вместо типизированного вложения.
- Итоговая картинка образа рендерится на клиенте в canvas — качество и размер зависят от устройства.
- Одежда «кладётся» на манекен вручную и почти никогда не садится ровно: у вещей нет привязки к анатомии манекена.
- Уведомления и бейджи — поллингом, хотя WebSocket уже есть.
- В git лежат `node_modules/`, `__pycache__/`, `media/`, `posts.js.bak`; `constructor.js` подключается в `base.html` дважды; `print()` вместо логирования; `tests.py` пустой.

Файлы `gen_diagrams.py`, `make_vkr.js` и всё, что относится к ВКР, — не трогай и не удаляй.

## 2. Цель продукта (видение)

**LOOKBOOK** (рабочее название, можешь предложить лучше в ADR) — мобильное приложение, где:
- каталог состоит из **реальных вещей**, которые команда (админы) фотографирует на телефон, а ИИ идеально «надевает» их на фирменный манекен;
- пользователь за минуту собирает образ: вещи **сами встают на своё место** на манекене (snap-to-body), остаётся только выбрать и при желании подправить;
- образы живут в красивой ленте, их можно лайкать, сохранять в коллекции, комментировать, «ремиксить» (открыть чужой образ в конструкторе и поменять вещи), покупать вещи по ссылкам;
- есть общение (личные сообщения с шарингом образов), подписки, уведомления в реальном времени и push.

Ключевые качества: **быстро (60 fps в конструкторе, холодный старт < 1.5 с), красиво (редакционная fashion-эстетика), надёжно (офлайн-кэш, ретраи), безопасно**.

## 3. Целевая архитектура

```
Android (Java) ──HTTPS/REST + WSS──► nginx ──► Django API (ASGI, uvicorn/gunicorn)
                                              ├─► PostgreSQL 16 + pgvector
                                              ├─► Redis (cache, Channels layer, Celery broker)
                                              ├─► MinIO (S3-совместимое хранилище медиа)
                                              ├─► Celery workers (default: превью, рендер образов, уведомления)
                                              └─► ML-service (FastAPI + PyTorch, GPU; очередь "ml")
Telegram Bot (aiogram) ── вход через Telegram, уведомления в Telegram (опционально)
Web Admin (Django admin + Unfold/Jazzmin) ── модерация, аналитика, каталог
```

### 3.1 Бэкенд (Python)
- **Python 3.12, Django 5.x, DRF, drf-spectacular** (OpenAPI 3 — единый контракт для Android), **django-filter**, **SimpleJWT** (access 15 мин + refresh с ротацией и blacklist), **Channels 4** с JWT-мидлварью для WebSocket, **Celery + celery-beat**, **django-storages[s3]** → MinIO, **Pillow / pyvips**, **psycopg 3**, **pgvector**, **structlog** + **Sentry** (опционально по env), **django-unfold** для админки.
- Раздели монолит `api` на доменные приложения: `accounts`, `social` (follow, лента), `catalog` (категории, вещи, манекены), `outfits` (образы, слои, коллекции, ремиксы), `engagement` (лайки, комментарии, сохранения), `messaging`, `notifications`, `studio` (админская съёмка и ML-джобы), `moderation` (жалобы, баны).
- Слои: `models` → `services` (бизнес-логика, транзакции) → `selectors` (оптимизированные запросы) → `api` (сериализаторы/вьюхи тонкие). Никакой логики в сериализаторах и вьюхах сверх валидации.
- Пагинация — **cursor pagination** везде, где списки. Все даты — ISO 8601 UTC, форматирование на клиенте.
- Счётчики — денормализованные поля, обновляемые через `F()` в транзакции + периодическая сверка в celery-beat.
- Поиск: PostgreSQL full-text (`SearchVector` с русской конфигурацией) + `pg_trgm` для опечаток; **поиск похожих вещей и образов** — по эмбеддингам в pgvector.
- Rate limiting (DRF throttling), валидация загрузок (размер, MIME по сигнатуре, EXIF-strip), CORS только для нужных origin.
- Итоговое изображение образа рендерит **сервер** (Celery, из слоёв в координатах манекена, 1080×1440 WebP + превью), клиент шлёт только состав и трансформации.
- Миграция данных: management-команда, переносящая пользователей, вещи, образы, лайки, комментарии, диалоги из старой схемы в новую.

### 3.2 ML-сервис (Python)
Отдельный контейнер `ml` (FastAPI + PyTorch, CUDA-образ; есть CPU-профиль с облегчёнными моделями для разработки). Подробно — раздел 5.

### 3.3 Мобильное приложение (Java)
- **Android, Java 17**, minSdk 26, targetSdk — последний стабильный. Gradle (Kotlin DSL для скриптов сборки допустим), **version catalog**.
- Архитектура: **single-activity + Navigation Component, MVVM**, модули: `:app`, `:core:network`, `:core:data`, `:core:designsystem`, `:core:common`, `:feature:auth`, `:feature:feed`, `:feature:constructor`, `:feature:profile`, `:feature:search`, `:feature:messages`, `:feature:notifications`, `:feature:studio` (только для админов).
- Библиотеки: **Hilt** (DI), **Retrofit + OkHttp + Moshi** (клиент по OpenAPI-контракту), **OkHttp WebSocket** (чат, уведомления, прогресс ML-джобов), **Room** (офлайн-кэш ленты, диалогов, каталога), **Paging 3** (LiveData/Guava-адаптеры для Java), **Glide** (+ WebP, плейсхолдеры blurhash), **CameraX** (съёмка в Студии), **WorkManager** (фоновая загрузка фото с ретраями), **Firebase Cloud Messaging** (push), **Material Components 3**, **Lottie** (микроанимации), **MotionLayout**/shared element transitions.
- Токены — в DataStore, зашифрованные ключом из Android Keystore. Автообновление access-токена через OkHttp `Authenticator`.
- Конструктор — **собственный `View`** на `Canvas` с `Matrix`-трансформациями, `ScaleGestureDetector` + свой детектор вращения, аппаратное ускорение, без аллокаций в `onDraw`. Undo/redo на паттерне Command.
- Deep links (`lookbook://post/123`, https app links), шаринг образа картинкой во внешние приложения.
- Тёмная тема, динамические шрифты, TalkBack-доступность, поддержка больших экранов (складные/планшеты — адаптивная сетка).

### 3.4 Вход в приложение
- **Вход через Telegram** (главный способ, сохраняет существующих пользователей по `telegram_id`): приложение запрашивает у API одноразовый `login_nonce` → открывает `https://t.me/<bot>?start=login_<nonce>` → бот (aiogram, отдельный контейнер) подтверждает пользователя и связывает nonce с `telegram_id` → приложение, опрашивающее/слушающее статус nonce, получает JWT и возвращается по deep link. Nonce живёт 5 минут, одноразовый.
- Альтернатива: вход по email с одноразовым кодом (OTP). Связка нескольких способов входа с одним аккаунтом.
- Аватар из Telegram подтягивается через Bot API, как сейчас, но в Celery.

### 3.5 Роли
- `user` — всё пользовательское.
- `moderator` — жалобы, скрытие постов/комментариев, временные баны.
- `admin` — всё выше + **Студия** (съёмка и публикация вещей в каталог), управление манекенами, категориями, аналитика.
- Первый админ создаётся командой `python manage.py create_admin --telegram-id <id>` (или `--email`). В приложении у админа появляется вкладка «Студия» в нижней навигации; для админов обязателен второй фактор (TOTP) при входе.
- Права — через DRF permissions + object-level проверки, покрыты тестами.

## 4. Функционал (что должно работать в итоге)

### Пользователь
1. **Онбординг**: 3 экрана с анимацией (идея → конструктор → лента), вход, выбор предпочтений (манекен по умолчанию, любимые стили) — используется для рекомендаций.
2. **Лента** «Для вас» и «Подписки»: вертикальные полноэкранные карточки образов, двойной тап — лайк с анимацией сердца, свайп вбок — карусель вещей образа (фото, название, цвет, стиль, описание, «Купить»), сохранение в коллекцию, шаринг, ремикс. Ранжирование: свежесть + вовлечённость + подписки + сходство эмбеддинга образа с предпочтениями пользователя; разнообразие авторов. Pull-to-refresh, плашка «N новых образов» через WebSocket.
3. **Конструктор**:
   - выбор манекена (мужской/женский; модель данных готова к нескольким телосложениям);
   - категории снизу, галерея вещей в bottom sheet с фильтрами (стиль, цвет, сезон, пол) и поиском, бесконечная прокрутка;
   - **вещь при добавлении автоматически встаёт на правильное место и в правильный слой** (использует fitted-слой из раздела 5), вещь той же «зоны» заменяет предыдущую (с возможностью оставить обе — для многослойности);
   - ручная доводка: перенос, масштаб, поворот, слой выше/ниже, отразить, удалить; кнопка «вернуть на манекен» (snap);
   - undo/redo, автосохранение **черновиков** (локально + синхронизация), «Похожие вещи» по долгому тапу;
   - публикация: описание, хештеги с автодополнением популярных, видимость (все/подписчики/только я); сервер рендерит итоговую картинку.
4. **Ремикс**: открыть чужой образ в конструкторе, заменить вещи, опубликовать со ссылкой на оригинал.
5. **Коллекции/сохранённое**: папки сохранённых образов и отдельных вещей («Хочу»).
6. **Профиль**: аватар (фото/Telegram/цвет), био, счётчики, сетка образов, вкладки «Образы / Ремиксы / Сохранённое», редактирование, выделение и массовое удаление своих постов, подписки/подписчики/друзья.
7. **Поиск**: пользователи, образы, вещи, хештеги; трендовые хештеги; поиск похожего по фото вещи (эмбеддинг загруженного фото → ближайшие вещи каталога).
8. **Сообщения**: список диалогов (закреп, удаление, непрочитанные), чат реального времени (отправка, редактирование, удаление, статус «прочитано», «печатает…»), **типизированные вложения**: образ, вещь, изображение. Офлайн-очередь отправки.
9. **Уведомления**: лайк, комментарий, ответ на комментарий, упоминание `@username`, подписка, ремикс вашего образа, новая вещь в любимом стиле. In-app в реальном времени (WebSocket) + push (FCM) + опционально в Telegram через бота. Группировка («Аня и ещё 5 оценили…»), настройки по типам.
10. **Комментарии**: ответы (один уровень вложенности), лайки, упоминания, удаление своих.
11. **Жалобы** на пост/комментарий/пользователя; блокировка пользователя.

### Администратор — «Студия»
1. **Съёмка** вещи через CameraX: оверлей-силуэт под выбранную категорию, индикатор горизонта (акселерометр), проверка резкости (дисперсия Лапласиана) и экспозиции прямо на устройстве, подсказки («слишком темно», «положите вещь целиком в рамку»). Можно фото спереди и сзади, можно выбрать из галереи.
2. **Загрузка** в фоне (WorkManager, ретраи, прогресс), создаётся `GarmentJob`.
3. **Живой прогресс** обработки по этапам через WebSocket.
4. **Экран проверки**: слайдер «до/после», превью на мужском и женском манекене, переключение вариантов (warp/генеративный), автозаполненные атрибуты (категория, цвет, стиль, сезон, узор, название-черновик, описание-черновик) с уверенностью модели — всё редактируемо.
5. **Ручная доводка посадки**: перетаскиваемые опорные точки вещи (плечи, воротник, талия, низ, рукава) поверх манекена → сервер быстро пересчитывает warp (< 2 с).
6. **Публикация** в каталог (или «в черновики каталога»), указание ссылки «где купить», цены, бренда. Повторная обработка другим режимом, архивирование вещи.
7. **Очередь** всех джобов (в обработке / ждут проверки / ошибки) с фильтрами.
8. Веб-админка: CRUD каталога и манекенов, разметка опорных точек манекена, модерация, дашборд (DAU/WAU, публикации, популярные вещи и хештеги, конверсия в «Купить», время обработки ML).

## 5. ИИ-пайплайн «вещь → идеально на манекен» (сердце проекта)

### 5.1 Система координат манекена
- Каждый `Mannequin` получает: изображение фиксированного размера (например 1200×1600, PNG с альфой), **маску тела** и **карту опорных точек** в нормализованных координатах `[0..1]`: макушка, шея (центр), плечи L/R, подмышки L/R, локти L/R, запястья L/R, грудь, талия L/R, бёдра L/R, пах, колени L/R, щиколотки L/R, стопы L/R. Разметка — в веб-админке (drag точек поверх изображения) + сид-фикстура для двух текущих манекенов из `frontend/static/images/`.
- Каждая `ClothingCategory` получает: **зону тела** (голова, верх, низ, всё тело, стопы, аксессуар), **слой по умолчанию** (порядок: тело < бельё < низ < обувь < верх < верхняя одежда < аксессуары < головной убор) и **маппинг** «опорные точки вещи → опорные точки манекена».
- Всё хранится так, что образ = манекен + список слоёв с трансформацией **относительно координат манекена**, а не пикселей экрана (важно: одинаковый вид на любом устройстве и при серверном рендере).

### 5.2 Этапы обработки (Celery-цепочка, очередь `ml`, каждый этап идемпотентен и логирует метрики)
1. **Контроль качества**: резкость, экспозиция, наличие вещи целиком (детектор). При провале — статус `needs_reshoot` с понятной причиной.
2. **Удаление фона**: BiRefNet (высокоточный matting) → уточнение альфа-краёв; fallback — `rembg` (u2net/isnet) на CPU.
3. **Нормализация**: баланс белого, выравнивание перспективы/поворота по маске, при низком разрешении — апскейл Real-ESRGAN.
4. **Классификация и атрибуты**: FashionCLIP / Marqo-FashionSigLIP zero-shot → категория, стиль, сезон, узор; доминантные цвета — k-means в пространстве Lab → ближайшее имя из фирменной палитры (русские названия). Сохранить **эмбеддинг** в pgvector (для «похожих вещей» и рекомендаций). Черновик названия/описания — шаблонно из атрибутов (опционально через LLM по env-ключу, выключено по умолчанию).
5. **Парсинг вещи и ключевые точки**: сегментация деталей (SegFormer, модель для одежды) + детектор ключевых точек одежды (модель, обученная на DeepFashion2-подобной разметке) → воротник, плечи, концы рукавов, талия, низ, для брюк — пояс, шаг, низ штанин.
6. **Посадка на манекен (режим `warp`, основной, детерминированный)**: по маппингу категории строим соответствие точек вещи и манекена → **Thin-Plate Spline**-деформация с регуляризацией (ограничение локального растяжения, сохранение пропорций принта) → клиппинг по маске тела там, где вещь должна «обнимать» тело → мягкая контактная тень (ambient occlusion по маске) отдельным слоем → результат: прозрачный PNG/WebP **в размере манекена, выровненный 1:1**. Для каждого манекена свой fitted-слой.
7. **Генеративный режим (`vton`, опциональный, для максимального реализма)**: диффузионная виртуальная примерка (CatVTON / IDM-VTON / OOTDiffusion — выбери по качеству и доступности весов) на изображении манекена → извлечение слоя одежды из результата (сегментация + разница с чистым манекеном) → тот же формат слоя. **Проверь лицензии весов** (многие — CC BY-NC-SA, только некоммерческое использование): зафиксируй в ADR и выведи предупреждение в админке. Режим включается флагом в env.
8. **Оценка качества посадки**: IoU с ожидаемой зоной тела, отклонение ключевых точек, артефакты по краям → `fit_score`. Если `fit_score` ниже порога — джоб уходит в «Требует проверки» с подсветкой проблемных зон.
9. **Выходные артефакты**: оригинал, cutout (свободная вырезка для галереи), fitted-слои для каждого манекена (+ тень), миниатюры WebP нескольких размеров, blurhash, атрибуты с уверенностью, эмбеддинг, ключевые точки (для ручной доводки).

### 5.3 Требования к ML-сервису
- API: `POST /jobs` (ссылка на исходник в S3, параметры), `POST /refit` (ручные точки → новый warp, синхронно, < 2 с), `GET /health`, `GET /models`.
- Модели грузятся один раз при старте, кэш весов на volume, версии моделей фиксируются и пишутся в результат джоба.
- Профили docker compose: `ml-gpu` (CUDA) и `ml-cpu` (облегчённые модели, для локальной разработки и CI).
- Бенчмарк-скрипт на наборе из 20 тестовых фото (положи их в `ml/tests/fixtures/`, сгенерируй или возьми с открытой лицензией): время по этапам, `fit_score`, сетка «до/после» в HTML-отчёт.

## 6. Дизайн

Сначала создай **дизайн-систему**, потом экраны. Результат — `docs/design/` (токены, компоненты, скриншоты экранов) и модуль `:core:designsystem`.

- **Эстетика**: редакционный fashion-журнал — много воздуха, крупная выразительная типографика заголовков (контрастная антиква/гротеск, например Playfair Display / Inter или Unbounded / Manrope — проверь поддержку кириллицы и лицензию OFL), фотографии — главный герой, интерфейс не спорит с одеждой. Нейтральная палитра (молочный, графит, тёплый серый) + один фирменный акцент. Полноценная тёмная тема.
- **Токены**: цвета (семантические: surface, onSurface, accent, danger…), типографическая шкала, отступы (сетка 4/8 dp), радиусы, тени/elevation, длительности и кривые анимаций. Никаких «магических» чисел в разметке.
- **Компоненты**: кнопки (primary/secondary/ghost/icon), чипы-фильтры, карточка образа, карточка вещи, аватар (фото/инициалы на цвете), bottom sheet, табы, пустые состояния с иллюстрацией, скелетоны загрузки, снекбары с действием «Отменить», диалоги подтверждения, бейджи.
- **Движение**: shared element переход карточка → просмотр образа, «падение» вещи на манекен с лёгкой пружиной при snap, сердце при лайке, haptic feedback на ключевых действиях (snap, лайк, публикация).
- **Экраны**: сплэш, онбординг, вход, лента, просмотр образа, комментарии, конструктор, публикация, профиль (свой/чужой), редактирование профиля, подписки/подписчики, поиск, коллекции, диалоги, чат, уведомления, настройки, Студия (камера, очередь, проверка, доводка точек, публикация).
- Каждое состояние экрана продумано: загрузка, пусто, ошибка сети (с ретраем), офлайн, нет прав.
- Доступность: контраст WCAG AA, touch-target ≥ 48 dp, contentDescription, масштаб шрифта до 200% без поломок.

## 10. Definition of Done для всего проекта
- Новый человек клонирует репо, копирует `.env.example` → `.env`, запускает `make up && make seed` и через 5 минут видит живое приложение с демо-данными в эмуляторе.
- Админ: `make create-admin`, входит в приложение, открывает Студию, фотографирует футболку — она появляется в каталоге и **садится на манекен без ручной подгонки**.
- Пользователь проходит полный цикл: вход → лента → конструктор → публикация → лайк/комментарий от второго пользователя → push → чат с шарингом образа.
- Нет секретов в коде, все проверки прав покрыты тестами, CI зелёный, дизайн консистентен на всех экранах в светлой и тёмной теме.
